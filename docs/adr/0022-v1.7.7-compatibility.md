# ADR 0022: Better Auth v1.7.7 compatibility delta

- Status: Accepted
- Date: 2026-10-12
- Better Auth reference: `better-auth` v1.7.7, tag commit `db02f233`
- Compared against: v1.7.1 (the earlier v1.7.0 port plus the v1.7.1 overlay)

## Context

Better Auth v1.7.2 to v1.7.7 changed server behavior that better-auth-go
ships: account identity, two-factor enrollment, password length checks,
origin checks, relative callback URLs, social provider token requests,
placeholder emails, PostgreSQL schemas and a live schema check. The rule for
this repository is that it is a port: Go matches the TypeScript behavior and
keeps a difference only for an existing documented Go rule or a clear safety
need.

The most important change is #11153. Better Auth 1.7.0 keyed accounts by a new
required `issuer` column; 1.7.3 removed it and went back to
`(providerId, accountId)`. better-auth-go had ported the 1.7.0 design to
`main`, but no release contained it.

## Decision

1. Pin the TypeScript oracle and upstream inventory to v1.7.7 and port every
   server change listed as **Ported** in
   `docs/compatibility/better-auth-v1.7.7.md`.
2. Remove the `issuer` account column and its API before any release ships
   them. Keep the v1.0.x unique index `uniq_provider_account` and also reject
   ambiguous keys on read, as upstream does. Ship tested SQL clean-up scripts
   for databases built from unreleased `main`.
3. Port the live schema check in Go form: it runs on the first request or on
   `Server.CheckSchema`, and only success is cached, because Go applications
   usually call `Migrate` after `New`.
4. Keep these differences: the verified-provider-email rule, the PayPal live
   default, PKCE for every provider that supports it, and the stricter
   PostgreSQL schema-name checks. Each is listed in the audit file and
   `PROGRESS.md`.

## Consequences

- better-auth-go v1.0.x databases upgrade with no schema change.
- Some error responses change (for example `PASSWORD_TOO_LONG` instead of
  `401`), and SQL-backed servers refuse requests until the schema matches.
  Both are listed under **Changed** in the changelog.
- The oracle and the three inventory scripts make later upstream drift visible
  in CI and in local runs.
