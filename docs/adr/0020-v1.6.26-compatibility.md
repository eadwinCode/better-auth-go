# ADR 0020: Better Auth v1.6.26 compatibility delta

- Status: Accepted
- Date: 2026-08-09
- Better Auth reference: `better-auth` v1.6.26, commit `a16b30e`
- Compared against: v1.6.25

## Context

Better Auth v1.6.26 contains eight server or storage changes relevant to a Go
compatibility audit. This repository implements a database-backed core and an
injected rate-limiter port, but it does not currently expose Better Auth's
secondary-storage contract or ship email-OTP, JWT, Redis storage, database
rate-limit storage, or OAuth-proxy plugins. Adding those systems solely to copy
a patch would bypass the repository's rule that each feature receives its own
threat model, adapter-independent contract, and black-box evidence.

The release also contains TypeScript client inference corrections and a
Next.js dynamic-import optimization. Those have no server-side Go equivalent.

## Decision

### Implemented now

1. Pin the TypeScript black-box oracle and upstream inventory to v1.6.26.
2. Add `CreatePlaceholderEmail`, which produces a stable address of the form
   `identifier@namespace.placeholder.invalid`. It preserves valid ASCII input,
   validates the local part and DNS namespace, and returns a typed sentinel
   error for invalid components.
3. Retain transactional primary-session deletion and add evidence that deleting
   a user with multiple sessions leaves no primary-storage session row.
4. Extend every transactional adapter's public conformance suite with commit
   and nested callback-scoped work in addition to rollback. The nested case
   proves callers can reuse the adapter supplied by `Transaction` without
   opening a second SQLite transaction.

### Deferred compatibility requirements

The following requirements become mandatory if their owning component is
implemented:

- **Secondary session storage:** user deletion removes every session value and
  the active-session index, plus database copies when configured. Batch lookup
  skips missing, malformed, or structurally invalid entries while returning
  every valid session in the request.
- **Email OTP:** invalid OTP checks return the same error for registered and
  unregistered emails; sign-up custom generators receive the explicit
  `email-verification` purpose; reset-password length validation occurs before
  atomic OTP consumption so the same OTP can be retried with a valid password.
- **JWT:** default JWK reads and creates resolve the adapter scoped to the
  current transaction. A key minted in a transaction commits and rolls back
  with that transaction on PostgreSQL and MySQL and cannot deadlock SQLite by
  escaping to the base connection.
- **Database rate-limit storage:** expired-row cleanup uses the configured
  background runner when present and is awaited when it is absent. Cleanup
  failures remain logged, best-effort, and do not change the request decision.
- **Redis storage:** key listing and clearing use cursor-based `SCAN`, escape
  prefix glob metacharacters, deduplicate listed keys, delete only non-empty
  pages, and document non-atomic partial failure and concurrent-keyspace
  behavior.
- **OAuth proxy:** Apple `form_post` `user` data survives the proxy round trip,
  is bounded and safely parsed, and is supplied to provider profile mapping.

The `jwtClient` and `oneTapClient` type-inference changes and the Next.js
`next/headers` import-promise change are excluded as TypeScript-runtime-only.

## Consequences

The stable core receives the compatible utility and stronger evidence without
claiming feature parity for missing plugins or storage layers. Future feature
work has precise v1.6.26 acceptance tests to implement. MySQL is explicitly a
future adapter/plugin evidence requirement because this repository currently
ships PostgreSQL, SQLite, MongoDB, and memory adapters only.
